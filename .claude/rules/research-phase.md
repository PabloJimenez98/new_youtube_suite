# Research/brainstorming phase rules

- This project has no fixed architecture yet. Never generate boilerplate
  code, folder scaffolding for "the app," or config files for a specific
  framework unless explicitly instructed in that session.
- When exploring options (model architectures, training approaches,
  data sources, tooling), always present them as a comparison
  (pros/cons/cost/effort) rather than picking one silently.
- Every research finding worth keeping goes into a file under
  `docs/research/` with a short filename describing the topic — don't
  leave findings only in chat history.
- When a decision is actually made, write it to `docs/decisions/` with:
  date, decision, reasoning, alternatives considered and why rejected.
- Keep responses during this phase concise; this is a thinking phase,
  not a delivery phase — depth over volume, but no filler.
